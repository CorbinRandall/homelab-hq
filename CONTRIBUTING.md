# Contributing

Issues and pull requests are welcome.

1. Fork the repository and create a focused branch.
2. Do not include real hostnames, addresses, MAC addresses, credentials, logs, or runtime data.
3. Run `go test ./...`, `go vet ./...`, and `docker build .`.
4. Describe behavioral changes and manual validation in the pull request.

Security vulnerabilities should be reported privately as described in [SECURITY.md](SECURITY.md), not through a public issue.
